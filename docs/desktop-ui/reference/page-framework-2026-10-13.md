# 页面框架实测（2026-10-13）

范围：Codex Desktop 的**壳层与页面框架**——标题带 / Rail / 页面导航器 / 主面怎么分层、每页怎么组成、
宽度与 hover 如何改变布局。全部数据来自本机运行中的 Codex Desktop，通过远程调试端口 9222 只读测量
（`scripts/cdp.mjs`）。窗口 2560×1320、dpr 1、浅色主题。

本文只记录实测与对照，不声称像素级一致；与 `rail-measurement-2026-10-05.md`、`shell-width-classes.md`
互补：那两份讲 Rail 自身与宽度类别，本文讲页面级框架。

## 1. 壳层区域模型（每页共用）

| 区域 | 实测（根坐标 px） | 说明 |
| --- | --- | --- |
| 根背景 `_Layout` | `[0,0] 2560×1320` | `color(srgb .9647 … / .85)`，实测约 246 |
| 标题带 `header` | `[0,0] 2560×46` | 无圆角；内部只有左上「返回 ChatGPT」按钮 |
| Rail `nav[aria=应用导航]` | `[0,44] 52×1272` | 贴标题带下方；背景与根背景同色（246） |
| Rail 端线 | `x=51`，1px | 实测色 236，把 Rail 与右侧分开 |
| 页面主面 `_PageSurface` | `[52,44] 2504×1272` | **四角圆角 12px**；距窗口右/下各约 4px |
| 页面导航器 | `[52,44] 288×1272` | 半透明白（`oklab(…/0.65)`），在 246 背景上实测 252 |
| 导航器↔主内容分隔线 | `x=340`，1px | 实测色 229 |
| 主内容 `_MainContentSurface` | `[340,44] 2216×1272` | 纯白 255，**直角**；带 1px 左描边 |
| 主内容视口 `_MainContentViewport` | `[341,44] 2215×1272` | 内容实际区域；顶部有 40px 渐隐 |

要点：

- **标题带 46 高**、Rail 从 **y=44** 起，二者底边基本对齐（我们 `Control.Titlebar = 44dp` 与之相符，
  差的 2px 是 header 自身边框）。
- **主面是一张圆角卡片**：`_PageSurface` 左上角在 (52,44)，四角均实测约 12px 曲率（左上在 Rail 与
  标题带背景之间最明显，右上/左下/右下也确认）。
- 导航器不是独立卡片：它是主面卡片内部的左半区（半透明白），与主内容之间只有 1px 分隔线。
- 我们目前：Rail 端线、导航器↔主内容分隔线方向一致（`BorderSubtle`）；**没有**「主面 12px 圆角卡片」。

## 4. 交互策略

### 4.1 宽度

| 宽度 | Rail | 导航器 |
| --- | --- | --- |
| 常规 | 常驻 52 | 展开：在主面卡片内推挤（`[52,44] 288`） |
| 窄 | 常驻 52 | 展开：浮层 |

参照桌面端未测到 rail→底栏断点（Rail 一直常驻）；`<640dp 浮层` 是本项目自己的决定
（`NavigatorLayout.NavigatorFloatBelow`）。

### 4.2 hover 有导航器的 Rail 项（**关键行为**）

| 当前页 | 导航器 | hover 有导航器的 Rail 项 |
| --- | --- | --- |
| 有导航器 | `[52,44] 288` | 只显示 tip，导航器不变 |
| **无导航器** | 宽 0 | **浮出该页导航器预览**，不导航 |

浮层导航器实测：`[56,48] 284×1264`（Rail 52 + 4，标题带 44 + 4），**圆角 8px**，纯白底，
`rgba(26,28,31,0.08) 0 0 0 1px inset` 内描边 + 阴影；**鼠标移开立即消失**。

我们目前**没有**这个预览（只出 tip）。

## 框架组件的圆角与描边（2026-10-13 晚）

对壳层框架组件做了一轮「圆角 + 轮廓线」实测对照（CDP DOM + 像素拟合）。

| 组件 | Codex 实测 | 本项目 | 结论 |
| --- | --- | --- | --- |
| Rail 项选中高亮 | DOM 12.5px，**像素拟合 ≈9** | `RailItemRadius = 10.dp` | 对齐（Δ1） |
| Rail 端线 | 1px，238/236（≈ `--alpha-05`） | `BorderSubtle` | 对齐 |
| 页面主面卡片 | 圆角 **12** + **0.5px 环 `rgba(26,28,31,.04)`** + 阴影 | 圆角 12 + 新增 `SurfaceRing` 0.5px 环 | 已补齐 |
| 主内容面 | 直角、纯白 | 直角、`Canvas` | 对齐 |
| 导航器面板 | 圆角 0、无描边、透明底 | 圆角 0、无描边、`Surface` | 基本对齐（底色非半透明） |
| 导航器↔主内容分隔线 | 1px，229 | `BorderSubtle` | 对齐 |
| 探索弹窗 | 圆角 20、**无边框**（环是阴影 spread） | 圆角 20、去掉了 0.5dp 边框 | 已补齐 |
| 个人资料菜单 | 圆角 **20**、无边框、90% 白、宽 **228** | `MenuRadius 20`、无边框、`MenuWidth 228` | 已补齐 |
| Composer | 圆角 **22** + **1px 环 `rgba(0,0,0,.04)`** | 圆角 22；`SurfaceRing` 1px 环（两处消费方） | 已补齐 |
| 标题带底线 | **无**（y=43 的 238 只是卡片自己的环，不跨 Rail） | Jewel TitleBar `borderColor` = 背景色 | 已补齐 |
| Rail tip | 深色胶囊，渲染圆角 ≈10 | `InverseSurface` 胶囊，10dp | 对齐 |

新增 token：`Colors.SurfaceRing`（light `#0A1A1C1F` / dark `#0AFFFFFF`）——参照用 0.5–1px 的 4% 墨色 hairline
把卡片/输入区与窗口底色分开，而不是常规 border。

**测量方法提醒**：DOM 的 `border-radius` 不等于绘制半径 —— Rail 高亮 DOM 12.5 实测只画到 ≈9；
浮层（tip/弹窗）因白底叠浅底、对比度低，拟合不可靠，弹窗圆角暂按 DOM 20 采纳，仍需肉眼复核。

### 导航器：嵌入态与预览态（2026-10-13 晚）

| | Codex 实测 | 本项目（对齐后） |
| --- | --- | --- |
| 嵌入态 | `[52,44] 288×1272`，背景**白 65%** 叠在卡片上 → 渲染 **252**；无自身圆角（被卡片 12px 角裁）、无阴影 | `Colors.NavigatorSurface` = `#A6FFFFFF`（浅色）→ 渲染 252 |
| 预览态（无导航器页 hover Rail 项浮出） | `[56,48] 284×1264`，**不透明白** → 渲染 **255**；圆角 8（渲染≈5）；**1px 内环 `rgba(26,28,31,.08)`** + 外阴影 | `SurfaceElevated` 255、圆角 5、`Colors.SurfaceRingStrong` 1px 环 + `shadow` |

两者在参照里**本来就不同**（252 半透明 vs 255 不透明白 + 环），本项目按各自的值对齐，不强行统一。

导航器**行的状态**（像素实测，行内空白处）：静止 252 / hover **240** / 选中 **240** —— 参照里 hover 与选中**底色相同**
（≈5% 墨色叠加），且行**无圆角、整行铺满**。本项目 `HarnessRow` 目前是「选中不透明 `SurfaceSelected` + 8dp 圆角、hover 无底色」，与此不同，待定。

### 卡片阴影：rail 右侧与主区上方的淡影来源（2026-10-13 晚）

rail 右侧与主区上方都有一层很淡的暗影，**不是 rail 自己的渐变或端线**，而是**页面主面卡片的投影溢出**。
参照卡片 shadow 的全值是：

```
0 0 0 0.5px rgba(26,28,31,.04)   # 0.5px 环
0 4px 16px 0 rgba(0,0,0,.05)     # 柔和投影，溢出卡片四周
```

实测：Rail 列（x=26）全程 **246 无渐变**；卡片左/上边缘外侧有 `245→244→238` 的渐降再跳进卡片白 255。
本项目已给卡片补上该投影（`dropShadow(radius 16, offsetY 4, black 5%)`，画在 clip 之前以允许溢出）。

**教训**：单列阈值扫描会把「投影的最深像素」误读成「1px 线」，也会把「溢出到 rail 的投影」误读成「rail 上的渐变」。
判定边缘时应当整行/整列扫描并比对多轴。
