# B1 标签栏与分屏验证

范围沿用「Codex UI 静态复刻」会话确认：替换标题栏内容，保留阴影，使用静态标签（`HarnessFixtureTabs`），主区继续渲染现有页面；包含左右分屏、互换、关闭和新增。

对照对象是**实时 Codex 调试端口**（CDP，端口 9222，只读探针 `scripts/cdp.mjs`）；本文件中的数值均为探针实测，不是推断。

## 各轮修正

1. 第一轮：按用户指出的四项差异（底色、图标、图标按钮行为、分割面板效果）逐项重测并修正。
2. 第二轮：两处结构性错误——标题栏那个按钮是**导航器开关**而不是标签栏开关；分屏**只切分导航器右侧的主区**，rail、导航器和侧面板都不属于分屏。
3. 第三轮：分割线样式、标题栏分段、隐藏导航器后的 rail 悬停预览、导航器状态跨页面共享（见下）。
4. 第五轮：标题栏的双重内缩、标题栏底色、新聊天只在首页且导航器折叠时出现、导航器预览的触发条件与底色、主区表面（其中「只给 Workspace 导航器画折叠控件」一条被第六轮推翻）。
5. 第六轮：①折叠控件回到 `mountsNavigator`（挂导航器的页面都能折叠），删除 `collapsesNavigator`；②修掉「首页折叠不了」的真正原因——Workspace 导航器的折叠态**根本没送到 shell**（见下）。
6. 第七轮：折叠后 rail 悬停预览的**闪烁**（两处），以及预览卡片**丢失的圆角/底色/描边/阴影**（实测实时 Codex 的 `data-slate-sidebar-peeking` 卡片后恢复）。
7. 第八轮（本轮，见下）：预览「起始位置偏高」——原先是 `Popup`，Compose Desktop 把 Popup 那一层夹在窗口内，预览被整体上移 16px；改为 shell 自己的 overlay 后落位与参考一致。

## 第八轮：预览的起始位置偏高（Popup 被窗口夹住）

用户反馈：悬浮导航器「起始位置偏高了」「请你仔细排查」。这次没有靠推断，而是把 `AppShell` 自己量到的布局直接打出来（临时诊断，取证后已删除）：窗口 1440×900、`density=1.0`、`fontScale=1.0`。

| | 修正前 | 修正后 | 参考（实时 Codex，2560×1320） |
| --- | --- | --- | --- |
| shell（rail 与页面卡片所在层） | `(0,45)…(1440,900)` | 同 | 标题栏之下 |
| 页面卡片 | `(52,45)…(1436,896)`，底 = 窗口 − 4 | 同 | `(52,44)…(2556,1316)`，底 = 窗口 − 4 |
| 预览卡片 | `(56,32)…(341,876)` ← **顶 32** | `(56,49)…(341,892)` | `(56,48)…(340,1312)` |
| 与页面卡片的关系 | 顶比页面卡片**高 13px** | 顶 = 页面卡片顶 + 4，底 = 页面卡片底 − 4 | 同左 |

**原因**：预览原先是 `Popup`。Compose Desktop 会把 Popup 这一层**夹在窗口内**——卡片 843 高再加给阴影留的 24px 是 867，放在 y=48 就要求底到 915，超出 900 高的窗口，于是这一层被对齐到窗口底边、整体上移 16px（诊断输出里 Popup 矩形的底正好打印为 900，就是被夹住的直接证据）。同一处 24px 也是上一轮「高度有点超出」的来源：它让 Popup 变高，看起来就是底部探出窗口。

**修正**：预览不再用 `Popup`，改成 **shell 自己的一层 overlay**（`Box(...).align(TopStart).offset(rail 宽 + 4, 4)`），因此

- 位置不再被窗口夹住；
- 高度直接取 shell 自身量到的高度：`peekCardHeight = shellHeight − NavigatorPeekInset * 3`（上让 4、下让 4 + 页面留白 4），不再用「窗口高 − 标题栏常数」——实测我们的标题栏是 **45**（`Titlebar = 44` 加上它自己的 1px hairline），按常数算会差 1px，现在也一并消掉；
- 阴影不需要再用 `NavigatorPeekShadowPad` 垫在 Popup 矩形里（该 token 已删除）；`dropShadow` 直接画在卡片上，溢出部分和页面卡片的阴影一样在 shell 外自然绘制；
- 它成了 shell 的最后一个子节点，仍然画在浮动抽屉、上下文面板与摘要面板的 scrim 之上（原来是 Popup，天然在最上层）。

## 第七轮：折叠后 rail 之间切换时预览闪烁 + 预览卡片样式

用户两项反馈：折叠导航器后在 rail 项目之间切换，悬浮导航器「瞬间打开又关闭」；悬浮的导航器「圆角之类的样式丢失了」。

### 闪烁（两处独立原因，都是真缺陷）

| 原因 | 代码证据 | 修正 |
| --- | --- | --- |
| **过期的 leave 事件清掉了 hover 态**：每个 rail 项用 `LaunchedEffect(hovered) { onHoverChanged(hovered) }` 报自己的悬停，离开 A 的 `false` 可能晚于进入 B 的 `true` 送达；而旧的 `onTriggerHover` 对任何 `false` 都无条件把 `triggerHovered` 置假，于是在指针还停在 B 上时 popover 判定"都离开了"，settle 到期后把刚打开的预览关掉 | `HoverPopoverState.onTriggerHover` 旧实现 | 只有**当前 hovered 的那个 key** 的 leave 才能清态；其它 key 的 leave 是过期事件，保持原状 |
| **越过没有导航器的 rail 槽（库 / 项目 / 探索）时预览被立刻销毁**：`previewKind` 直接用「当前悬停项的目的导航器」，那一项没有导航器时立刻为 null，Popup 被销毁（无 settle），下一项再重建 —— 每次经过就是一个闪 | `AppShell` 的 `previewKind?.let { … }` 直接驱动 Popup | 新增 `shownPeekKind`：有预览就立刻换成它，悬停到没有导航器的槽时**保留上一个**、并按 popover 的 settle 关闭；popover 自身 settle 到期（指针离开 rail）立即清空。移动过程里 Popup 不再销毁重建 |

### 预览卡片样式（实测实时 Codex，只读 hover）

策略是折进面板里的，之前测的是面板盒子（aside `[0,44,340,1272]`），而**可见的卡片是它里面的 `[data-slate-sidebar-content]`**，展开折叠时样式完全不同。本次用只读 CDP 悬停一个 rail 项后实测：

- `[data-slate-sidebar-peeking=true]`、aside 仍是 `[0,44,52,1272]`（rail 不被遮）；
- 卡片 `[56,48,284,1264]`：x 56 = rail 52 + **4**，y 48 = 标题栏 44 + **4**，宽 284 = 288 列 − 4，底 1312 = 面板底再让 4；
- `margin: 4px 0px 4px 4px`（上/右/下/左）；
- `border-radius: 8px`（CSS `calc(var(--radius-xl-base) = .75rem − var(--spacing) = .25rem)`）；
- `background-color: rgb(255,255,255)`——**不透明**（非折叠列那种 `color-mix(surface 65%, transparent)`，实测 `oklab(… / 0.65)`）；
- `box-shadow: inset 0 0 0 1px rgba(26,28,31,0.08), 0 4px 16px 0 rgba(0,0,0,0.05)`，其中 `--hairline` 在本机解析为 1px、`--shadow-card: 0px 4px 16px 0px #0000000d` 与页面卡片**同一个** token（`--app-shell-page-surface-shadow` 也用它）。

复刻（`HarnessTokens` 新槽位）：`NavigatorPeekInset = 4.dp`、`NavigatorPeekRadius = 8.dp`、`Control.CardShadow`（页面卡片与预览共用）、`Colors.NavigatorPeekSurface`（亮 `0xFFFFFFFF` / 暗 `0xFF202020`），描边用已有的 `SurfaceRingStrong`（`0x141A1C1F` = 8% 墨）1px。卡片的阴影、圆角、底色、描边按上表落位。（当轮还有一个给 Popup 矩形垫阴影的 `NavigatorPeekShadowPad = 24.dp`，第八轮改用 shell overlay 后已删除。）

**高度订正（用户验收指出「高度有点超出」）**：第一版把卡片写成"Popup 矩形内缩 4px 后 `fillMaxSize`"，而 Popup 矩形为了给阴影留位置又加了 24px —— 这 24px 直接进了卡片高度，于是卡片高 `H−32`（底部到 `H+16`，探出窗口 16px）。当轮改成**显式尺寸**：`peekCardWidth = peekWidth − 4`、`peekCardHeight = (窗口高 − 标题栏 − 页面留白) − 8`。当时记的"与实时实测逐项相等"只对**尺寸**成立，**落位并不相等**——第八轮的实测证明这个 Popup 被窗口夹住、整体上移了 16px；现在高度取自 shell 自身的高度，落位也按 shell 内 `(rail 宽 + 4, 4)` 放置。

## 第六轮：Workspace 导航器的折叠态没送到 shell

现象（用户两次验收）：首页点标题栏的折叠控件、按 ⌘B 都折叠不了；插件 / 定时任务在展开时连控件都没有。

两处彼此独立的缺陷：

| 缺陷 | 证据 | 修正 |
| --- | --- | --- |
| 展开时插件 / 定时任务 / 设置没有折叠控件 | 实时 Codex 里折叠是**应用级**命令 `toggleSidebar`，只由功能开关 `sidebarCollapsible`（`bi={…,sidebarCollapsible:!0,…}`，默认 true）把关，与路由无关；唯一与路由有关的是新聊天字形（`!hideUnreadBadge && !isSidebarOpen && route === "home"`） | 第五轮加错的 `PageShellSpec.collapsesNavigator`（只给 Workspace 导航器画控件）已删除，规则回到 `mountsNavigator` |
| 首页 / 会话**永远折叠不了**（控件在，点了没用） | `AppShell` 取 Workspace 导航器用的是它的**参数** `navigator`（`NavigatorKind.Workspace -> navigator`），折叠态从该对象读；而 `HarnessApp` 构造这个参数时是 `workspaceState.copy(workspaceId, workspaceLabel)`，**没有 `mode`** ——`navigatorMode` 只写进了 `AppShellState.workspace`，而 shell 从不读那个字段。于是首页恒为 `Pushed`，控件与 ⌘B 翻的是一个 shell 不看的状态；`navigatorOnScreen` 也恒为 true，这正是「折叠时 hover 不预览」在首页同样发生的原因（第五轮 #7 只改了预览的触发条件，没能救它） | `HarnessApp` 在构造 `navigator` 时带上 `mode = navigatorMode`；`AppShellState.workspace` 直接复用同一个对象（`workspace = navigator`），一个导航器只有一个模式来源 |

现在在所有挂了导航器的页面上，折叠都走同一条链路：控件 / ⌘B → `toggleSidebar` → `navigatorMode = Collapsed` → 该页 `NavigatorState.mode` → `navigatorLayout(mode, width) == Hidden` → shell 不画被推入的列、主区吃满宽度；首页折叠后 `navigatorOnScreen` 变 false，rail 悬停预览随之生效。

## 实现

- 标签状态由 DesktopHarnessWindow 持有，不再等待 HarnessApp 的 SideEffect 发布。
- 拖动使用窗口坐标，只有释放点位于主区才分屏；移动已有分屏成员可互换两侧。
- 关闭任一分屏成员后保留另一成员。不会生成两侧同 ID 的分屏。
- 新标签使用单调编号并检查重复，关闭后新增不会复用仍打开的标签 ID。
- 分屏由窗口标题栏的标签状态驱动，但**只作用于 shell 的主区**（`HarnessMainRegion` / `LocalHarnessMainRegion`）。
- Jewel clientRegion 只注入真实标题栏中的交互元素。普通 Compose 测试不依赖 Jewel 内部 CompositionLocal。
- 交通灯占位由 Jewel/JBR 提供；Jewel 在测量子节点后加入 native inset，macOS 普通窗口按实测 88px（`TitlebarLeadInset`）预留测量预算，全屏不使用该预留。这条 inset 也是标题栏自成一个坐标系的来源，见第五轮。
- 标题栏阴影作为同一 Box 内的底部覆盖层保留，主区不再插入重复条带。

| 标签间细线 | 1×12，`[1699,16,1,12]`，`opacity:0`（所属标签被选中/悬停时隐藏） | `TabSeparator = 12dp`，邻居悬停时隐藏 |
| 尾部簇 | 1×16 细线 `[2483,14,1,16]`、进入完整视图 `[2490,8,28,28]`、隐藏标签页 `[2524,8,28,28]`，右留白 8px | `TitlebarTrailingRule = 16dp`，`Spacing.Two` 尾留白，`ms-auto` 贴右缘 |

结论：`lead = max(区域左缘, 簇宽)`（第五轮修正：这些 x 都是**窗口坐标**，而标题栏自身被 Jewel 按 macOS 窗口控件内缩了 ~88px，所以实现里必须再减去标题栏的窗口原点，否则整条标题栏右偏 88px。见「第五轮」#5/#6）；
- 导航器展开时 `lead = 52 + 288 = 340`，细线正好在 340；
- 导航器隐藏时列宽仍由簇撑开（实测 230），细线落在第一窗格段内部，窗格内容再让 8px（实测 238）。
  这也解释了为什么"隐藏导航器后左窗格标签起点是 349"（历史实测，当时导航器展开：340 + 8 + 1）。

## 分割面板效果（本轮修正）

- **分隔线样式（用户指出）**：实测 `role=separator cursor-col-resize` 是一个 16px 热区，线本身 `opacity: 0`，悬停/拖动时才显出 1px 竖向渐变（`transparent → text/25% → transparent`）；旧实现画的 18% 水平阴影是错的，已删除。
- **分屏范围**：左侧是一个 `aside.app-shell-left-panel = [0,44,340,1272]`，rail 与导航器合成一列、整窗高只出现一次；分屏把导航器右侧主区一分为二。复刻把分屏下移到 `AppShell` 主区，rail / 导航器 / 侧面板各只组合一次；拖放目标也随区域收窄。
- **窗格宽度并非 50/50**：`splitFraction` 默认 0.5、钳制 0.2..0.8，拖动传像素增量，状态侧读当前比例，避免一次手势里用过期比例。
- **两个窗格各自的标签行**：历史实测左窗格标签 x=349、右窗格 x=1582（各自段起点 + 8），说明标签条按窗格分开。复刻现在每个窗格都画一条标签行，各自以本窗格的标签为选中项，并列出全部标签（Codex 在部分模式下只显示所在窗格的标签；这是刻意的简化，见「未完成」）。

## 隐藏导航器后 rail 项的悬停（本轮实测并实现）

- 实测：导航器隐藏时悬停拥有导航器的 rail 项，折叠的左面板加上 `data-slate-sidebar-peeking=true`（同时 `overflow-visible`、`z-40`），隐藏的整列按原宽（rail 52 + 导航器）重新出现在页面之上；被悬停的 rail 项报 `aria-expanded=true`，预览显示的是**那个目的页**的导航器，且不会发生导航。**第七轮更正**：当时记的「面板自身的盒子仍是 `[0,44,340,1272]`——无圆角、无阴影、无遮罩」量的是 aside 盒子；折叠态实测 aside 是 `[0,44,52,1272]`，真正的可见卡片是它内部的 `[data-slate-sidebar-content]`，即第七轮实测的 `[56,48,284,1264]` 圆角卡片。
- 本次探针再次确认：rail 项悬停时面板可见，而标题栏里的开关仍报 `显示侧边栏`（即状态上仍是隐藏），两者一致。
- 复刻：`AppShell` 在隐藏（`NavigatorLayout.Hidden`）时对 `previewKind` 渲染 `navigator-peek` 悬浮层，宽度取"推入状态"的同一计算（不依赖折叠态宽度）；位置与高度按第八轮：shell 内 `(rail 宽 + 4, 4)`、高度 = shell 高度 − 12；没有导航器目的页的 rail 项不预览。
- 第五轮补正两处：触发条件原本写成 `!navigatorMounted`，于是**当前页自己也挂了导航器时**（首页/会话）折叠后永远不预览——现改为"页面上没有可见的导航器列"（`!mountsNavigator || layout == NavigatorLayout.Hidden`），rail 的 tooltip 同步抑制；预览当时是 `Popup`，背后没有 shell（第八轮改成 shell 自己的 overlay，见第八轮）。**底色的做法在第七轮被替换**：当时先画 `AppBackground` 再叠半透明的 `NavigatorSurface`，实测实时卡片本身是**不透明白底 + 4px 内缩 + 8px 圆角 + 1px 描边 + 卡片阴影**，现按实测画卡片（见第七轮）。
- **但首页仍然不预览**，原因是这一页的 `layout` 从来不是 `Hidden`（折叠态没送到 shell，见「第六轮」）：触发条件再对也没用。第六轮修好折叠后，首页的折叠 + 悬停预览同时成立。

## 导航器状态跨页面共享（本轮修正）

- `HarnessApp` 里原来是四个页面各自的 `SidebarMode`；实测 Codex 全应用只有一个折叠模式，故改为**一个** `navigatorMode`，写进每个 `NavigatorState.mode`（页面内容仍各自持有）。
- 只有挂了导航器的页面能折叠（`pageShellSpec(page).mountsNavigator`）；`NavigatorKind.None` 的页面没有模式可共享，标题栏也不画该控件。
- 第五轮一度把控件收窄为「只有 Workspace 导航器可折叠」（`collapsesNavigator`），依据是误读——实时 Codex 的折叠能力由应用级 `sidebarCollapsible` 开关决定（见第五轮 #2），与路由无关：插件页、定时任务页同样能折叠，收窄后这三页展开时就没有入口了（用户指出「折叠不了」）。现已删除该属性，规则回到 `mountsNavigator`。
- 插件页收起、设置页选中等自动收起路径改为写同一个 `navigatorMode`，不再各写各的。
