# Batch AN — localize the plugin detail "unsupported" descriptors

Date: 2026-10-11. Entry: `entry-an1`.

## Why this batch

Batches AI and AM taught the local plugin inventory to surface Apps and MCP / hooks / scripts
**names** on the plugin detail page. But the page still printed the parser's internal declaration
tokens verbatim — `apps (unsupported)`, `MCP (unsupported)`, `hooks (unsupported)`,
`scripts (unsupported)`, `skill attachments (unsupported)`, `other capabilities (unsupported)` —
inside an otherwise Chinese UI. The "未支持的资源" list also sat *before* the real Skills / Apps /
capability sections, so it read like the main content instead of a footnote.

## Change detail

- New private `unsupportedAssetLabel(descriptor)` maps the six tokens defined by
  `DesktopUserPlugins.DESCRIPTORS` to user-facing Chinese. Any value the page does not recognise
  passes through unchanged, so nothing is silently hidden.
- The block moved from before the Apps section to after the `capabilities` rows, so it now reads as
  a qualifier on the concrete sections above it.
- `filterNot`: `DesktopInstalledPluginRepository` already turns the `apps (unsupported)` descriptor
  into a Chinese `PluginAppsState.Unavailable(reason)` rendered in the Apps section, so the raw
  descriptor is dropped **only** in that case to avoid duplicate, mixed-language messaging. Every
  other descriptor still shows.
- No parser, schema, or repository change; no new capability is claimed.
